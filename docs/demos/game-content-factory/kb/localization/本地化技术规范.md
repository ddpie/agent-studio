# 本地化技术规范

> 本文档为通用游戏本地化技术参考，供翻译/审校人员及 AI 翻译代理使用，用于校验译文的技术正确性。

---

## 1. 文本膨胀率参考表

以中文为源语言翻译至目标语言时，文本长度的典型膨胀系数：

| 目标语言 | 膨胀系数 | 备注 |
|---------|---------|------|
| 英语 (EN) | ~1.5x | 英文通常比中文长 50% |
| 日语 (JA) | ~1:1 | 信息密度相近，但假名水平占位大于汉字 |
| 韩语 (KO) | ~1.1x | 韩语分写规则导致略长 |
| 德语 (DE) | ~1.8x | 复合词极长，需特别注意 UI 空间 |
| 法语 (FR) | ~1.5-1.7x | 含冠词、介词结构较多 |
| 西班牙语 (ES) | ~1.5-1.8x | 动词变位和冠词增加长度 |
| 俄语 (RU) | ~1.6-2.0x | 西里尔字母词汇较长，词尾变化丰富 |
| 阿拉伯语 (AR) | ~1.5x | RTL 排版，需额外考虑双向文本混排 |

**注意**：膨胀率为参考均值，实际因文本类型（UI 短文本 vs 叙事长文本）波动较大。短文本膨胀率通常高于长文本。

## 2. UI 文本字符限制

不同 UI 元素的标准字符数上限（以英文字符计）：

| UI 元素 | 英文限制 | 中文参考 | 说明 |
|---------|---------|---------|------|
| 按钮 (Button) | 8-12 字符 | 2-4 字 | 单行，不可换行 |
| 菜单项 (Menu Item) | 15-20 字符 | 5-8 字 | 含图标时可用空间更少 |
| 工具提示 (Tooltip) | 80-120 字符 | 30-50 字 | 可多行，但不宜超过 3 行 |
| 推送通知 (iOS) | 40 字符 | 15-18 字 | 超出部分被截断 |
| 推送通知 (Android) | 65 字符 | 25-30 字 | 折叠态显示限制 |
| 对话框标题 (Dialog Title) | 20-30 字符 | 8-12 字 | 单行居中 |
| 系统消息 (System Message) | 100-200 字符 | 40-80 字 | 可换行，但需保持简洁 |

**核心原则**：当源文翻译后超过目标字符限制时，译者必须**缩写**(abbreviate)而非**截断**(truncate)。缩写保留语义完整性，截断可能造成歧义或信息缺失。

其他语言限制按膨胀系数换算：`目标限制 = 英文限制 x (1 / 目标语言膨胀系数)`。

## 3. 变量与占位符规范

### 3.1 占位符类型

| 类型 | 格式示例 | 说明 |
|------|---------|------|
| 命名占位符 | `{player_name}`, `{item_count}`, `{reward_name}` | 可安全重排顺序 |
| 位置占位符 | `%s`, `%d`, `%f` | 严禁重排 |
| 索引占位符 | `%1$s`, `%2$d` | 支持重排（依赖索引号） |
| HTML/富文本 | `<b>`, `<color=#FF0000>` | 保持标签完整 |

### 3.2 规则

1. **绝对禁止翻译**占位符内的变量名（如 `{player_name}` 中的 `player_name`）
2. **绝对禁止重排**无索引的位置占位符（`%s`, `%d` 必须保持原始顺序）
3. 命名占位符和索引占位符**允许重排**以适应目标语言语序
4. 占位符前后**不得添加或删除空格**（除非目标语言语法要求）
5. **不得改变大小写**（`{PlayerName}` 不可变为 `{playername}`）

### 3.3 常见错误

| 错误类型 | 错误示例 | 正确示例 |
|---------|---------|---------|
| 翻译变量名 | `{玩家名称}` | `{player_name}` |
| 添加多余空格 | `{ player_name }` | `{player_name}` |
| 修改大小写 | `{PLAYER_NAME}` | `{player_name}` |
| 重排位置占位符 | 源: `%s got %d` → 译: `%d 获得 %s` | 保持 `%s ... %d` 顺序 |
| 丢失占位符 | 译文中遗漏 `{reward_name}` | 确保所有占位符均出现 |

## 4. 复数与语法性规范

### 4.1 各语言复数形式数量

| 语言 | 复数形式数 | 示例 |
|------|-----------|------|
| 中文/日语/韩语 | 1（无语法复数） | 1 个道具 / 99 个道具 |
| 英语 | 2 | 1 item / 2 items |
| 法语/西班牙语 | 2 | 通常 0 和 1 为单数形式 |
| 俄语 | 3 | 1 предмет / 2 предмета / 5 предметов |
| 波兰语 | 3 | 1 przedmiot / 2 przedmioty / 5 przedmiotow |
| 阿拉伯语 | 6 | zero/one/two/few/many/other |

### 4.2 语法性别

- **德语**：3 种性（阳/阴/中），影响冠词（der/die/das）、形容词词尾
- **法语**：2 种性（阳/阴），影响冠词（le/la）、形容词形式
- **俄语**：3 种性，影响动词过去时、形容词变位
- **西班牙语**：2 种性，影响冠词（el/la）和形容词

### 4.3 技术实现建议

对于涉及数量和性别的动态文本，推荐使用 ICU MessageFormat：

```
{count, plural,
  one {You have {count} new message}
  other {You have {count} new messages}
}
```

翻译时需按目标语言的 CLDR 复数规则提供所有必需的复数形式。

## 5. 日期/时间/数字格式

### 5.1 日期格式

| 市场 | 格式 | 示例 |
|------|------|------|
| 中国 | YYYY年MM月DD日 / YYYY-MM-DD | 2026年5月17日 |
| 美国 | MM/DD/YYYY | 05/17/2026 |
| 欧洲（多数） | DD/MM/YYYY 或 DD.MM.YYYY | 17/05/2026 |
| 日本 | YYYY年MM月DD日 / YYYY/MM/DD | 2026年5月17日 |
| 韩国 | YYYY년 MM월 DD일 | 2026년 5월 17일 |

### 5.2 时间格式

| 市场 | 格式 | 示例 |
|------|------|------|
| 中国/日本/韩国/欧洲多数 | 24 小时制 | 14:30 |
| 美国/加拿大(英语区) | 12 小时制 | 2:30 PM |

### 5.3 数字格式

| 市场 | 千位分隔符 | 小数点 | 示例 |
|------|-----------|--------|------|
| 中国/美国/日本/韩国 | , (逗号) | . (句点) | 1,234,567.89 |
| 德国/法国/俄罗斯 | . (句点) 或 空格 | , (逗号) | 1.234.567,89 |
| 印度 | , (逗号，非三位一组) | . (句点) | 12,34,567.89 |

### 5.4 货币规范

- 虚拟货币**绝对禁止**使用真实货币符号（$, EUR, Y 等）
- 虚拟货币使用游戏内专属图标或自定义名称
- 真实货币展示须符合当地格式（如 $1.99 vs 1,99 EUR）

## 6. 编码与字体

### 6.1 编码要求

- 所有文本文件**必须使用 UTF-8 编码**（无 BOM）
- 禁止使用 GBK、Shift-JIS、EUC-KR 等遗留编码
- 换行符统一使用 LF（`\n`），不使用 CRLF

### 6.2 字体需求

- CJK 文字需要支持双字节字符的字体
- 推荐字体回退链（fallback chain）：

```
主字体 → CJK 字体 → Emoji 字体 → 兜底字体(防豆腐块)
```

- 兜底字体必须覆盖 BMP（Basic Multilingual Plane）常用区段

### 6.3 换行规则

| 语言类型 | 换行规则 |
|---------|---------|
| CJK（中文/日文） | 任意字符间可断行，但不得在注音（ruby）标注内部断开 |
| 韩语 | 以空格为单位断行（韩语为分写语言） |
| 西方语言 | 空格或连字符处断行，不得在单词中间断开 |
| 阿拉伯语/希伯来语 | RTL 方向断行，不得破坏字母连接形式 |

### 6.4 特殊字符注意

- 中文标点为全角（，。！？）、西文标点为半角（,.!?）
- 日语长音符号（ー）不等于中文破折号（——）
- 省略号：中文用"......"（6点）或"......"（2个三点），西文用"..."（3点/1个字符 U+2026）

## 7. LQA（本地化质量保证）检查清单

翻译完成后，须逐项检查以下内容：

- [ ] **占位符完整性**：所有变量均存在且格式正确，未被翻译或修改
- [ ] **无截断**：译文在目标 UI 中完整显示，未被裁切
- [ ] **术语一致性**：专有名词与术语表保持一致
- [ ] **字符限制**：译文长度在目标元素限制范围内
- [ ] **日期/数字格式**：符合目标市场的本地格式规范
- [ ] **无编码错误**：无 `□□□`、`???`、`&#x;` 等乱码字符
- [ ] **性/数一致性**：语法性别和复数形式正确
- [ ] **RTL 渲染**：（适用语言）双向文本排版正确，标点位置正确
- [ ] **换行合理**：未在单词或语义单元中间断行
- [ ] **语域/敬体**：正式度与上下文匹配（如日语敬语层级）
- [ ] **上下文正确**：同一源文在不同上下文中的翻译是否区分处理
- [ ] **功能性测试**：含变量的文本在实际拼接后语法通顺
